# 012 · 原理圖規範

版本：v0.1 · 2026-09-30

> 這些規則原本散在 011 §1.1、devlog 和對話裡，集中在這裡。
> **畫任何一頁之前先看這份**，尤其是 net 名稱 —— 已經踩過三次命名坑。

---

## 1. Net 命名

### 1.1 電源軌

```
+5V_VBUS · +5V_USB · +5V_HDMI
+3V3
+1V8_SOC · +1V8_AUDIO · +1V8_HDMI · +1V8_DVDD · +1V8_AVDD · +1V8_PLVDD
+1V5 · +0V9
GND
```

⚠ **+5V_HDMI 是 HDMI 座上的 +5V（DDC 上拉用）**，與 +5V_VBUS 分開命名 ——
它接到外部螢幕，要獨立看待。

⚠ **+1V8_AUDIO 不叫 +1V8_AVCC** —— 和 ADV7511 的 +1V8_AVDD 只差一個字母。

### 1.2 訊號

```
低有效      _N 結尾              SYS_RESET_N、PHY_RESET_N、ADV_RESET_N
全大寫      不混大小寫
底線分隔    不用連字號            RMII_TXD0 不是 RMII-TXD0
不用特殊字元 ✗ ~{NAME}  ✗ NAME#   匯出 netlist / BOM 到其他工具時會出事
```

⚠ **符號上的 pin 名稱與 net 名稱是兩回事**：

```
pin 名稱    ~{RESET}       KiCad 會渲染成上橫線，很好，保持
net 名稱    SYS_RESET_N    純 ASCII
```

### 1.3 ★ 已經踩過的三次命名坑

```
+3.3V   vs  +3V3        大小寫外的寫法差異 → 兩條不同的 net
+1V8_SoC vs +1V8_SOC    只差一個字母大小寫 → 更難目視發現
（第三次是 pin 名稱與 net 名稱混淆）
```

**KiCad 把名稱不同的 net 當成完全不同的網路，而 ERC 只會提示
「net 只有一個連接點」—— 很容易被當成雜訊忽略。**

**對策：net 名稱一律從本文件複製貼上，不要手打。**

## 2. 用哪一種標籤

| 方式 | 快捷鍵 | 作用範圍 | 用途 |
|---|---|---|---|
| **電源符號** | `P` | 全域 | 電源軌、GND |
| 區域標籤 | `L` | 同一頁 | 頁內避免拉長線 |
| **全域標籤** | `Ctrl+L` | 全域 | 跨頁訊號 |
| 階層標籤 | `H` | 該頁↔父圖紙 | 本專案不用 |

**電源一律用電源符號，不用標籤。** 差別不在能不能連，在 ERC：

```
電源符號   內含隱藏的 power_in 腳 → ERC 會檢查這條 power net 有沒有被驅動
一般標籤   ERC 眼中就是普通 net → 忘了接穩壓器也不報錯
```

**不用階層標籤的理由**：它要在子頁放標籤、再到父圖紙的 sheet 符號拉線，
每條訊號要維護兩個地方。階層標籤適合「同一子電路重複使用多次」的場合，
本專案每頁都是獨一無二的，全域標籤就夠。

## 3. 元件欄位

| 欄位 | 必填 | 內容 | 例 |
|---|---|---|---|
| Reference | 自動 | 位號 | `R9` |
| **Value** | ✅ | 阻值/容值，給人讀 | `240R` |
| **Footprint** | ✅ | 封裝 | `Resistor_SMD:R_0603_1608Metric` |
| **LCSC** | ✅ | ★ JLCPCB 下單靠這個 | `C25091` |
| Tolerance | 選填 | 僅在同阻值有兩種容差時 | `1%` |

`LCSC` 是自訂欄位（`E` → Add Field），JLCPCB 的 BOM 匯入認這個欄位名。

**容差不寫進 Value** —— LCSC 料號本身就決定了阻值、容差、封裝、材質。

### 3.1 Value 寫法

```
電阻   240R · 4R7 · 10K · 51.0K · 232K      R 代表 Ω，也可當小數點
電容   0.1uF · 220nF · 1uF · 22uF
電感   1.0uH · 1.5uH · 2.2uH
IC     用完整料號   AP2112K-1.8 · APX803-29SAG-7
```

⚠ 不要用 `240Ω`、`10kΩ` —— 特殊字元在匯出時容易出事。

## 4. 被動件規格

### 4.1 封裝統一 0603

```
Resistor_SMD:R_0603_1608Metric
Capacitor_SMD:C_0603_1608Metric
```

理由（見 [006-assembly.md](006-assembly.md)）：

```
手焊難度   0603 比 0402 容易一個等級，而本專案有兩片要自焊
DC bias    同容值下 0603 的衰減小於 0402（概念 ⑧）
面積       對 100×100mm 不是問題
```

### 4.1.1 ⚠ 兩個例外

**① C5~C8 的 22 µF 用 0805，不是 0603**

```
理由   22 µF 在 0603 的 DC bias 衰減太嚴重（概念 ⑧）
       011 §2.4 定的料號 C45783 就是 0805 X5R
位置   RY1303 三路 buck 的輸出電容
```

**② C14 220 µF SMD 電解**

```
位置   USB-A Host 的 +5V_USB bulk（011 §6.3）
理由   USB 2.0 §7.2.4.1 要求 downstream port bulk ≥ 120 µF，
       而 MLCC 0603 最大約 22 µF，做不到
封裝   SMD 電解，典型 6.3×6.3 mm，耐壓 ≥10 V
```

```
位置   USB-A Host 的 +5V_USB bulk（011 §6.3）
理由   USB 2.0 §7.2.4.1 要求 downstream port bulk ≥ 120 µF，
       而 MLCC 0603 最大約 22 µF，做不到
封裝   暫用 Capacitor_SMD:CP_Elec_6.3x7.7，選定實際料號後要對尺寸
```

**全板的封裝分布**（電源頁完成時）：

```
C_0603   11    一般去耦與小容值
C_0805    4    22 µF ×4（DC bias）
CP_Elec   1    220 µF ×1（USB bulk）
R_0603    9
L_4020    3
SOT-23-5  3    AP2112K ×2、TPS2051B
SOT-23    1    APX803
(留空)    1    U1 RY1303 —— QFN 封裝待核對
```

### 4.2 容差：全部用 1%

| 用途 | 是否必須 1% | 為什麼 |
|---|---|---|
| 分壓（決定輸出電壓） | **必須** | 直接疊在 FB 容差上 |
| DZQ 240R | **必須** | DDR3 規範，決定所有終端阻抗 |
| RC 延遲（47K） | 5% 就夠 | 9.6ms 變 9 或 10ms 無所謂 |
| 上拉（10K） | 5% 就夠 | 只要拉得上去 |

**但全部用 1%** —— 0603 的 1% 與 5% 幾乎同價，統一可以：

```
少一種料號（BOM 種類數直接影響 JLCPCB 的 feeder fee $3.07/種）
免去「哪顆該用哪種」的判斷與出錯機會
```

## 6. ★ 更新符號的地雷

```
工具 → 從庫更新符號
  ☐ 重設欄位 / Reset Fields        ← 絕對不要勾
  ☐ 重設欄位可見度
  ☐ 重設欄位效果
```

**2026-09-30 踩過一次：勾了之後 22 個被動件的 Value 全被覆寫成庫預設的 `C` / `R` / `L`。**
接線完好，但值全失 —— 而且如果沒發現就會一路帶到下單。

**原則：對話框裡有「重設 / reset / 覆寫」字樣的一律不勾。**

### 6.1 替代做法

若只是要改符號定義本身（名稱、電氣型別），
**直接改 `.kicad_sch` 裡的 `lib_symbols` 快取**比走更新流程安全：

```
KiCad 開檔時用檔案內的快取渲染 → 完全不必執行那個會清值的動作
```

⚠ 但僅限**不改幾何**的情況：

```
改名稱、改電氣型別    → 座標不變，安全
改位置、改邊、改索引  → 符號高度改變 → 所有腳位 Y 座標位移 → 已畫的線全部對不上
```

（同日也踩過一次：把 pin 16 從符號上方移到左側，左側由 8 列變 10 列，
更新後 U1 的 21 支腳有 16 支掉線，且 pin 9 誤連到 +5V_VBUS。）

## 6.2 ★ git pull 之後必須重開 KiCad

```
git pull 下來的改動   不會反映到已經開著的 KiCad 視窗
KiCad 存檔           是把整頁的記憶體狀態整個寫回去，不是做 diff
```

**所以 pull 進來的修正，會在下次存檔時被靜默覆蓋。**

2026-10-02 踩過一次：`2413442` 已經把 mcu 頁的 C17~C19 從 `DIP-24` 改成 `C_0603`，
但 KiCad 還開著舊狀態，畫完 unit 2 存檔時整頁寫回去，三顆 footprint 又變回 DIP-24。

**危險的地方在於 git 只會顯示「檔案被修改」，看不出是哪些修正被洗掉了。**

```
規則   git pull 之後、以及任何人在檔案層改過 .kicad_sch 之後，
       一律關掉 KiCad 再重開
```

## 7. 驗證流程

**每畫完一個功能區塊就跑一次，不要全部畫完再驗。**

```bash
python hardware/scripts/check_power_rails.py
```

它會自己叫 kicad-cli 產 netlist，然後驗：

```
SW → 電感 → 是否落在期望的軌
FB 分壓：R_top 在軌上、R_bot 在 GND、中點接 FB，並回算輸出電壓
輸出電容數量
EN 不可浮接
孤立 net（只有一個連接點）
```

### 7.1 為什麼非跑不可

原理圖階段最危險的錯誤是**看不出來的那種**：

```
看得出來   元件放錯、值填錯、線沒連          眼睛掃一遍就發現
看不出來   線連到「長得很像的另一支腳」       只有 netlist 看得見
           值被更新符號清掉                  只有比對才發現
```

本專案已經靠它抓到三次：

```
① FB 接到別的通道的腳（兩路電源同時失控）
② LDO 的 VIN/EN 接地、VOUT 並聯到另一顆的輸出（會燒件）
③ 22 個元件值被更新符號清掉
```
