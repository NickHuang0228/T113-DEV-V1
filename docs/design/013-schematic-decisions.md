# 013 · 原理圖收尾階段的決定

版本：v1.3 · 2026-10-10（§12 重新稽核 netlist）

這份記錄「把剩下八張子圖紙畫完」時被迫做出的決定。
每一條都是前面文件留下的待確認項，或是畫圖時才浮現的衝突。

格式統一為：**問題 → 選了什麼 → 理由 → 代價**。
「代價」那一欄最重要 —— 沒有代價的決定通常是沒想清楚。

---

## 1. BOOT-SEL 怎麼接（解掉 007 §5.3）

**問題**：PC4 / PC5 同時是 SPI0 的 MOSI/MISO 與 BROM 的 BOOT-SEL strap，
但 datasheet 沒給真值表，不知道該上拉還是下拉。

**查法**：MangoPi MQ-R 是同一顆 T113-S3，它的原理圖 p.3 直接印了真值表。
文字抽取只用來定位，實際接法是把那塊區域 render 成圖目視確認的
（專案規則「抽出來的文字用來定位，不用來定案」的第五次命中）。

```
SEL[1:0]
  00:  NOR > NAND
  01:  SD  > NOR  > Other
√ 10:  SD  > NAND > Other          ← MangoPi 打勾的是這個
  11:  SD0 > EMMC2 > EMMC2_USR > Other
```

MangoPi 的實際接法（⚠ **下面是 MangoPi 的編號，不是本板的** ——
全專案重編 designator 時掃到這裡，一度把它們一起改掉了）：

```
VCC3V3 ─┬─ R75 10K  ─ SPI0_MISO ─ R76 NC   ─┬─ GND
        └─ R77 NC   ─ SPI0_MOSI ─ R78 10K  ─┘
         → SEL1 = 1, SEL0 = 0  →  10
```

**選了什麼**：本板要 **01（SD > NOR > Other）**，剛好與 MangoPi 左右對調。

```
SPI0_MISO (PC5, BOOT-SEL1)   10K 下拉   → 0    storage 頁 R66 焊、R65 不焊
SPI0_MOSI (PC4, BOOT-SEL0)   10K 上拉   → 1    storage 頁 R67 焊、R68 不焊
```

**理由**：本板有 SD、有 SPI NOR、沒有 NAND。選 10 的話第二順位會去找不存在的
NAND，白等一輪 timeout。

**代價**：兩個位置都留焊盤（各兩顆電阻、其中一顆不上件），多四個焊盤面積。
換到的是「改 boot order 不必飛線」—— strap 是上電那一刻的事，改不了就是改不了。

## 2. FEL 按鍵接哪支腳（解掉 004 §7）

**問題**：004 §7 寫「FEL 按鍵接哪一支腳必須查 datasheet」，一直沒查到。

**選了什麼**：**不需要專用 FEL 腳。**

BOOT-SEL = 01 時 BROM 依序試 SD → NOR → Other，兩個都失敗就落到 USB FEL。
要「主動」進 FEL，只要讓 SEL0 在上電瞬間變成 0：

```
SW2（usb 頁）：SPI0_MOSI ─[R76 1K]─ 按鍵 ─ GND
按住上電 → 1K 壓贏 storage 頁的 10K 上拉 → SEL[1:0] = 00（NOR > NAND）
         → NOR 是空的、又沒有 NAND → 直接進 USB FEL
```

**理由**：這是從 §1 的真值表推出來的，不是猜的。而且它不需要額外的 SoC 腳位。

**代價**：按住 SW2 時 1K 掛在 SPI0_MOSI 上。只在上電瞬間按，之後放開；
就算一直按著，3.3V/1K = 3.3mA 在 T113 的驅動能力內，而且 FEL 模式本來就不用 SPI。

## 3. 排針 GPIO 從 10 支變 7 支

**問題**：五個週邊控制訊號沒有 SoC 腳可用 ——
HDMI_PD、HDMI_INT_N、PANEL_RESET_N、USB_EN、USB_OC_N。
T113-S3 的 129 腳已經全部配完，unit 6 剩下的 16 支未用腳全是類比
（FMIN / LINEIN / MICIN / TVIN / TP-X,Y），不能當 GPIO。
唯一的來源是 PG bank，而 PG 16 支全部給了排針。

**選了什麼**：拿三支，另外兩支用不佔腳的做法。

| 訊號 | 做法 | 失去什麼 |
|---|---|---|
| HDMI_INT_N | **PG12**（原 HDR_GPIO8） | — |
| HDMI_PD | **PG14**（原 HDR_GPIO9） | — |
| PANEL_RESET_N | **PG4**（原 HDR_GPIO7） | — |
| USB_EN | 100K 上拉常開（usb 頁 R75） | 軟體關不掉 USB 埠 |
| USB_OC_N | 測試點 TP13 | 軟體讀不到過流狀態 |

**理由**：判準是「缺了會不會影響 bring-up」。

```
HDMI_INT_N      HPD 偵測是本專案的練習重點（002 bring-up 清單）。
                輪詢也能做，但中斷才是 driver 真正的寫法 —— 練不到就失去意義。
HDMI_PD         002 §1.4 明確要求「MIPI 模式時 ADV7511 要保持關閉」。
                它同時是 I2C 位址的 strap，所以 GPIO 與下拉電阻兩個都要。
PANEL_RESET_N   DSI 面板的初始化序列一定要能拉 RESET，
                沒有它連 DCS 命令都送不進去。MIPI 是本專案第一優先。
USB_EN          常開就好。失去的是「軟體重啟卡死的 WiFi dongle」這個方便。
USB_OC_N        限流保護是 TPS2051B 內部做的，不靠軟體。
                失去的只是「軟體知道發生過」。
```

**代價**：**與 SPEC 不符** —— SPEC 寫排針純 GPIO 10 支，實際 7 支。
排針仍有 7 GPIO + 2 組 I2C + UART1 + UART0 console 備援，夠用，但這是明確的縮水。
如果之後覺得排針比 HDMI 中斷重要，改回去只要動 mcu 頁的三個標籤名稱
（`rename_nets.py` 反向跑）。

## 4. ADV7511 的 I2C 掛在排針的 TWI1 上

**問題**：ADV7511 的控制 I2C 需要接到 SoC，但 PG7/PG8（TWI1）已經給了排針。

**選了什麼**：**共用**。display 頁的 SCL/SDA 直接用 `HDR_I2C1_SCL` / `HDR_I2C1_SDA`。

**理由**：I2C 本來就是匯流排，掛多個裝置是正常用法。
ADV7511 的位址是 0x39 / 0x3D（7-bit），不是常見的衝突區。

**代價**：
- 外接模組的位址不可與 ADV7511 衝突 —— 已寫在排針頁的圖紙註記上。
- 訊號經過 mcu 頁的 100R 串聯電阻（R33/R34）。400kHz 下 RC 延遲可忽略。
- net 名稱叫 `HDR_I2C1_*` 有點誤導（它不只給排針用）。
  改名要動 mcu 頁的手畫內容，不值得。

**2kΩ 上拉放在 display 頁**（R53/R54），因為 ADV7511 是這條匯流排上
唯一一定存在的裝置（002 §3.2.2 要求 2kΩ ±5%）。

## 5. HDMI 的 TMDS 不放 ESD，USB 的資料線放

同一個判斷在兩處走向相反的結論，所以值得記下來。

| | HDMI TMDS | USB 2.0 HS |
|---|---|---|
| 速率 | 1.485 Gbps/pair | 480 Mbps |
| 可容忍的 ESD 元件電容 | < 1 pF | ~1.5 pF 可接受 |
| 符合的料 | 只有 0201 單線件（ESD131-B1-W0201） | USBLC6-2SC6，SOT-23-6 |
| 手焊 | 做不到 | 可以 |
| **決定** | **V1 不放** | **放，每對一顆（D1/D2/D3）** |

**為什麼不「只放一半」**：
① 在 TMDS 走線上留「不焊的焊盤」本身就是 stub，比不放更糟。
② 只保護慢速線（HPD / DDC / CEC）會造成「有保護」的錯覺。

**代價**：HDMI 熱插拔的 ESD 直接打在 ADV7511 的 TMDS 輸出上。
板子要小心拿。V2 改用整合式 HDMI ESD 陣列，placement 階段就留位置。

## 6. MIPI FPC 的腳位是暫定值

**問題**：002 §2.3 寫得很白 ——「面板 FPC 的 pin 定義各家不同，下單前務必用實體面板比對」。
但沒有面板就畫不出接頭，而 MIPI 是第一優先。

**選了什麼**：用常見的 40-pin 4-lane 排法（差分對之間夾 GND）先畫，
並在**圖紙上**用最大的字標明「這張腳位表是暫定值，不是定案」。

**理由**：有一張待核對的圖，比沒有圖更接近完成。
但警告必須在圖上，不是在 markdown 裡 —— 佈線時看的是圖。

**代價**：這一頁的佈線在選定面板、逐腳核對完之前**不能開始**。
已經寫成圖紙上的核對清單。

**IOVCC 用 0Ω 二選一**：R77（+3V3，預設焊）/ R78（+1V8_SOC，不焊）。
焊錯邊的代價是面板報廢，所以核對面板 datasheet 之前不要上電。

## 7. 幾個「漏了就不會動，但圖上看不出來」的被動件

這一類最危險：netlist 完全合法、ERC 不會報、所有線都接得好好的，
要到 bring-up 才發現。集中列在這裡。

| 元件 | 位置 | 漏了會怎樣 |
|---|---|---|
| **R41 4.7K ↑** | net 頁，RTL8201F pin 8 RXDV | 內部弱下拉 = MII 模式。本板只拉了 RMII 的七條線，**完全不通** |
| R42 4.7K ↓ | net 頁，pin 12 CLK_CTL | REF_CLK 方向反了，50MHz 沒人提供 |
| R44 4.7K ↓ | net 頁，RXER/FXEN | 進了光纖模式 |
| R43 4.7K ↑ | net 頁，MDIO | 開汲極沒上拉，讀不到 PHY 暫存器（PHY 像不存在） |
| R40 2.49K 1% | net 頁，RSET | MDI 驅動電流不對，鏈路跑不起來 |
| R50 887R 1% | display 頁，R_EXT | ADV7511 內部參考電流沒設定，晶片不動 |
| R52 10K ↓ | display 頁，PD/AD | I2C 位址與 PD 極性都不確定 |
| R75 100K ↑ | usb 頁，USB_EN | USB-A 一直沒電（EN 是高有效，GPIO 上電是高阻態） |
| C59/C60 22pF | net 頁，25MHz 負載電容 | PHY「時而能通時而不能」 |

共通點：**接錯或漏掉都不燒件，但板子不會動。**
對照之下，電源頁踩過的兩次（FB 接錯通道、LDO 的 VOUT 並聯）是會燒件的那一類。
兩類都要防，但防法不同 —— 前者靠逐條核對 datasheet 的 strap 表，後者靠 netlist 驗證。

## 8. 這一輪新增的工具

| 腳本 | 用途 |
|---|---|
| `sym_pins.py` | 印出符號的腳位與座標。寫生成器前一定要先看 —— 座標算錯的線頭差幾 mm，圖上完全看不出來 |
| `dryrun_sheet.py` | 不碰檔案就檢查生成器：非格點座標、designator 撞號/跳號、net 清單 |
| `rename_nets.py` | 唯一會動到手畫內容的腳本，所以多三道保險（KiCad 關閉、git 乾淨、舊名稱剛好一次） |
| `run_all.py` | 八張子頁的生成順序有相依性，不能亂跑 |
| `schlib.Page` | 把「從腳位拉線接到標籤/電源/電阻」收成方法。偏移量算錯就是接不上 |
| `schlib.RAIL_SYMBOL` | net 名稱 → power 符號的查表。直接拿 net 名稱當 lib_id 會生出不存在的符號，開檔整頁變問號 |

### 這一輪修掉的三個「安靜的錯」

比報錯更危險的是不報錯：

1. **`check_schematic.py` 的 kicad-cli 路徑寫死 Program Files**，
   KiCad 10 實際裝在 `%LOCALAPPDATA%` → 整支檢查器一直安靜地沒跑。
   修好後立刻抓到 `U6 pin 91 (AGND)` 沒接到 GND。
2. **`sheet_uuid_of()` 從子頁自己的內容抓路徑** ——
   剛建立的空白子頁裡沒有這個資訊，會回傳 `None`，
   結果是那一頁所有元件的 reference 變成 `?`。
3. **`sym_pins.py` 不處理符號繼承** —— CH340N 是從 CH330N 繼承的，
   只看自己的區塊會得到「共 0 支腳」這種看起來像答案的錯答案。

## 10. 真的跑進 KiCad 之後抓到的（ERC 1309 → 0）

前九節是「設計上的決定」。這一節是**把生成器真的跑出檔案、
用 kicad-cli 跑 ERC** 之後才浮現的問題 —— 全部是「圖看起來完全正常」的那一類。

因為 KiCad 當時開著不能寫檔，做法是把 `hardware/` 複製一份到暫存區，
在副本上跑完整流程、跑 ERC、修、再跑，來回七輪。

### ① lib_symbols 是空的 —— 1309 個違規裡的 1204 個

`.kicad_sch` 裡的 `(lib_symbols)` 不是「方便離線開啟」的選配，
**它是 KiCad 判斷「這顆元件的腳在哪裡」的唯一依據。**

```
快取空的 → KiCad 不知道任何一支腳的座標
         → 畫好的線一條都接不上
         → 619 unconnected_wire_endpoint + 316 pin_not_connected
            + 163 isolated_pin_label + 94 label_dangling
```

八張圖，每一條線都是斷的，而在 KiCad 裡打開看起來完全正常。
補上之後 1309 → 105。工具是 `fill_lib_symbols.py`。

兩個做這件事容易做錯的地方：
- **命名**：外層要完整 lib_id（`"Device:R"`），內層子符號要去掉庫名（`"R_0_1"`）。
  KiCad 用「外層去掉 `lib:`」去配內層，配不上就是沒有腳。
- **繼承**：`CH340N` 是從 `CH330N` 繼承的，自己的區塊一支腳都沒有。
  照抄等於存了一顆沒有腳的元件 —— 要攤平。

### ② 兩個 Type-C 的 D+ / D- 接反了　★ 最危險的一個

符號座標的 Y 軸向上、原理圖向下，所以 `dy` 要變號。第一版算錯了：

```
            符號座標          原理圖 y       第一版寫的
A7  D-     (15.24,  2.54)    y - 2.54       y + 2.54   ← 其實是 A6 (D+)
B7  D-     (15.24,     0)    y              y          ✓
A6  D+     (15.24, -2.54)    y + 2.54       y + 5.08   ← 其實是 B6
B6  D+     (15.24, -5.08)    y + 5.08       y + 7.62   ← 沒有腳
```

**兩個 Type-C 的差分對都會接反**，而原理圖上線都好好的。
ERC 只是碰巧因為 A7 落空才報出來 —— 如果四個 y 全部一致地偏移，
它會是一張完全合法、完全接錯的圖。

教訓：**抄符號座標的時候，dy 要不要變號必須每一支腳分別確認**，
不能「這一組對了，下一組照抄」。

### ③ 十顆 0Ω 畫了兩次

002 §1.2 要求 PD0~PD9 與 ADV7511 之間串 0Ω。
那十顆**早就畫在 mcu 頁了**（R10~R19，手畫），display 頁又串了一顆。

```
U6 PD0 ──┬── MIPI FPC
         └─[R10 0Ω]── LCD0_D2 ─[R51 0Ω]── ADV7511 D2     ← 多一顆
```

0Ω + 0Ω 電氣上沒事，但：10 顆多餘的料、20 個多餘的焊點，
而且 **「0Ω 焊盤距主幹 ≤0.5mm」這條規則失去意義** —— 要距離哪一顆？
已移除 display 頁的那十顆。

### ④ 整塊板沒有晶振

`isolated_pin_label`（DXIN / DXOUT / X32KIN / X32KOUT 四個標籤接不到東西）
才抓出來：**24MHz 晶振根本沒畫**。沒有它 SoC 不會動。

規格照 MangoPi MQ-R v1.6 p.3（同一顆 T113-S3，已量產驗證）：

```
Y2  24MHz      CL=18pF     負載電容 22pF ×2    DCXO，Cshunt 6.5pF
Y3  32.768kHz  CL=12.5pF   負載電容 22pF ×2    RTC，Cshunt 1.1pF
```

### ⑤ unit 6 / unit 7 被放了兩份，而且在紙面外

那兩個 unit 的符號**已經在 KiCad 裡手動放好了**，生成器又放一份，
座標還寫死在 y=320 / y=442 —— A3 只有 297mm 高。
後果是 14 個 `different_unit_net`：同一支腳出現在兩個地方、各自接到不同的 net。

改成**從檔案裡讀出既有的擺放位置**，並加上「超出紙面就中止」的檢查。

### ⑥ T 形接點沒放 junction

線頭落在另一條線的「中間」時，KiCad 不會自動連，而圖上看起來是連著的。
網路頁的地隔離網路踩到這個。

### ⑦ 電源軌「沒人驅動」—— 不是錯，但要標

降壓器的輸出走 SW 腳 →[電感]→ 輸出節點。電感是被動件，
所以 ERC 在輸出節點上找不到任何 `power_out` 腳，判定沒人驅動。
`+3V3` / `+1V5` / `+0V9` / `GND` / `HDMI_5V` / `+5V_VBUS` / 三組 1.8V 都是這樣。

解法是 PWR_FLAG（不進 BOM、不上板）。
⚠ 它會讓 ERC 閉嘴，所以只能用在確實有電的地方。

### ⑧ 三條檢查規則本身是錯的

工具抓工具的錯：

| 規則 | 原本 | 問題 |
|---|---|---|
| `check_schematic.py` 的 kicad-cli 路徑 | 寫死 `Program Files` | KiCad 10 裝在 `%LOCALAPPDATA%` —— **整支檢查器一直安靜地沒跑**。修好後立刻抓到 U6 pin 91 AGND 沒接地 |
| RGB 接線：T113 與 ADV7511 要同一條 net | 直接比 net 名稱 | 中間隔著 0Ω，本來就是兩條 net。改成「能穿過一顆 0Ω」 |
| 同一條訊號掛多顆電阻就報 | 兩張圖紙時夠用 | 現在 `SPI0_MOSI` 正常就有 3 顆（FEL + BOOT-SEL 對）。改成抓真正的 bug 特徵：**同一條 net 上有 SoC 的兩支腳** |

第一條最值得記：**比報錯更危險的是不報錯。**

### ⑨ 符號庫的縮排有兩種

KiCad 內建庫用 tab，本專案 `gen_*_symbol.py` 產生的庫用 2 個空格。
比對樣式只寫 tab 的話，自建符號一律「找不到」—— 而那看起來像庫壞了。

## 11. 把圖輸出成 PDF 來看 —— ERC 過了不等於圖能看

ERC 歸零之後，用 `kicad-cli sch export pdf` 把十一頁輸出成圖，一頁一頁看。
**接線 100% 正確，但排版很糟** —— 而 ERC 對這一類問題完全沉默。

### 問題都是同一個根源：文字比符號寬得多

```
腳距              2.54 mm
"+1V8_DVDD"       約 20 mm
```

十三支電源腳各放一個電源符號，文字就疊成一團墨。
**圖上看不清楚等於沒畫**，而佈線的人看的就是這張圖。

### 三個改法

**① 同一條軌走一條匯流排（`Page.pin_bus`）**

```
pins ──┐
pins ──┤
pins ──┤ 垂直匯流排
pins ──┤
pins ──┴──────── [+1V8_DVDD]     只放一個符號，從最上面那列往外拉
```

各組的出口在不同的 y，文字就不會互相蓋。
ADV7511 的 unit 1 左側因此**依「接哪一條軌」重排腳位順序**（不是依腳號）——
同軌的腳要相鄰，才走得出一條匯流排。符號與生成器兩邊要同時改。

**② 藏掉 `#PWR` 與 `#FLG` 的 reference**

真實原理圖不顯示這些。每一顆電源符號多一段沒有資訊量的文字，
十幾顆擠在一起就把真正要看的 net 名稱蓋掉了。

**③ 直立的電阻電容，文字往旁邊讓**

`symbol()` 原本只支援垂直偏移，所以直立元件的 ref/value 會壓在自己的接線上。
加上 `ref_dx` / `val_dx`，直立時往右讓 5.08mm。

### 剩下的是距離不夠，逐處加大

```
晶振的兩顆負載電容   ∓3.81 → ∓12.7     原本兩個 "22pF" 疊在一起
Type-C 的 CC 下拉    stub 22.86 → 38.1  原本壓在 D± 的標籤文字上
LC 濾波的目的端      +22.86 → +27.94    原本與電容的 value 疊
接頭的電源標籤       比訊號標籤再往外    兩種文字原本同位置
測試點的 Value       不要與全域標籤同字串 否則兩段文字疊在同一點
圖紙註記             整體上移            最後一行原本壓到圖框
```

### 這一節的教訓

**ERC 驗的是「連線對不對」，不是「圖能不能看」。**
兩者都要驗，而後者只能把圖輸出來、一頁一頁看。
已經把 `kicad-cli sch export pdf` 加進收尾流程。

## 12. 重新稽核 netlist —— 抓到整塊板最重要的那顆晶片沒有去耦

ERC 歸零、圖也看過之後再做一次獨立稽核：**不看圖，只看 netlist**。
逐條問「這支腳接到哪、這條軌上有什麼」。

### ★ T113-S3 的 23 支電源腳，一顆本地電容都沒有

```
+1V8_AUDIO   3 支腳（LDOA-OUT 28 / AVCC 89 / HPVCC 97）   0 顆
             011 §6.1 白紙黑字寫「LDOA-OUT (28) 2.2 µF 到地」—— 漏了
+0V9         5 支腳（VDD-CORE ×2、VDD-SYS ×3）            只有 buck 端的 C7 22µF
+1V5         2 支腳（VCC-DRAM，DDR3）                      只有 C8 22µF
+1V8_SOC     5 支腳                                        只有 C11 1µF
+3V3         6 支腳                                        有，但都在別顆 IC 旁邊
```

對照之下，ADV7511 那頁（程式生成的）13 支電源腳各有一顆 0.1µF。
**整塊板最重要的晶片反而是去耦最差的那一顆** —— 因為 mcu 頁是手畫的，
當時只拉訊號線，去耦從來沒補。

後果不是「不會開機」，是「時好時壞」：1.2GHz 核心 + DDR3，
本地沒有電荷水庫 → 電流瞬變時軌壓塌陷 → 隨機當機、DDR training 失敗。
這種問題查起來要好幾週，而且每次重現條件都不一樣。

補上 23 顆（`gen_mcu_decoupling.py`）：每條軌「幾支電源腳就幾顆 0.1µF」，
核心與 DDR 另加 10µF 本地 bulk，+1V8_AUDIO 放 011 §6.1 指定的 2.2µF。

⚠ 這只決定「有幾顆」。**真正決定效果的是 layout** —— 每顆要貼著它負責的那支腳、
via 直接下地平面。擺遠了就只是 BOM 上多幾顆料（概念 08）。

### 稽核時一併確認、沒有問題的

```
T113 129 支腳        全部接到 net，一支不漏
只接到單一元件的訊號  0 條
Value 欄位空白        0 顆
自動命名的 net        53 條，逐條查過都是「腳 + 它的被動件」的正常兩端線段
                      （PB2~PB7/PF6/PD22/PE10/PE12/PE13 → TP1~TP11，
                        PG0~PG15 → 各自的串接電阻，VRA1/2 → 0.47µF…）
RGB666 的 D 索引      22 條逐條對過 002 §3.2，含 PD12/PD13 的非連號陷阱
```

### designator 重編：R 跳 20 號、C 跳 11 號、J 跳 1 號 → 全部連號

```
C  1~84   84 顆   跳號 無
R  1~78   78 顆   跳號 無
J  1~9     9 顆   跳號 無
```

**驗證方法：比「連線集合」，不比 net 名稱。**
把每條 net 化成 `frozenset{(ref, pin)}`，改名前後整體比對 ——
253 條裡 251 條完全相同，剩下 2 條是我刻意把 +1V8_SOC 與 +1V8_AUDIO
的編號順序對調（電路相同）。

不能用 net 名稱當 key：自動命名的 net 名稱本身含 designator
（`Net-(J3-Pad9)`），改名後名字也跟著變，比對會出現一堆假陽性。

### ⚠ 重編時踩到的兩個坑

**① 鏈式替換。** 由大到小分批取代看似安全，其實不是：
`C78 → C67` 之後，`C67 → C56` 這條規則又吃了一次，變成 C56。
**來源範圍與目標範圍重疊時，一定要單趟替換**（一個 regex 掃一次、用函式查表）。

**② 掃到別人板子的編號。** 文件裡引用 MangoPi MQ-R 原理圖的
`R74 / R75 / R76 / R77 / R78 / C50` 全部被一起改掉了 ——
那是**別人板子的 designator**，改了之後對照原始 PDF 就對不上。
已還原，並在 §1 的引用處加上警語。

**③ f-string 的編號掃不到。** `f"C{73+i}"` 這種寫法，文字替換看不到實際編號，
結果那一頁跟別頁對不起來。已把 `gen_mcu_decoupling.py` 改成一顆一顆寫死。
