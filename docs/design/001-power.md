# 001 · 電源樹與上電時序

---

## 1. 電源樹

```
Type-C VBUS 5V ──┬─ 保護（自恢復保險絲 + TVS）
                 │
                 ├─ DC-DC #1 ─▶ 1.1V   VDD_CPU + VDD_SYS      ~600 mA
                 ├─ DC-DC #2 ─▶ 1.8V   VCC_PLL / MIPI / DDR IO  ~200 mA
                 ├─ LDO  #1  ─▶ 3.3V   VCC_IO / PHY / IT66121   ~400 mA
                 ├─ LDO  #2  ─▶ 3.3V_A 類比／音訊（可選，隔離用） ~50 mA
                 └─ 直通      ─▶ 5V     USB-A Host（含限流開關）   500 mA
```

⚠ 各軌電壓與電流為初估，**必須以 T113-S3 datasheet 的電源章節為準**，列在 SPEC 的待確認清單。

---

## 2. 為什麼用分離式 DC-DC/LDO 而不是 PMIC

| | 分離式 | PMIC（如 AXP 系列） |
|---|---|---|
| 除錯 | **每一軌可獨立量測、獨立斷開** | 一顆黑盒子，內部時序看不見 |
| 上電時序 | 用 EN 腳串接，**順序自己控制** | 靠內部狀態機，改不了 |
| 料況 | 通用料，好買好換 | 專用料，可能缺貨 |
| 成本 | ~$3/套 | ~$2/顆 |
| 板面積 | 較大 | 較小 |

**第一塊 Linux 板選可觀測性，不選省面積。** 開不了機的時候，能用電表逐軌量是最重要的事。

---

## 3. 上電時序

SoC 對電源上電順序有要求，順序錯可能導致閂鎖（latch-up）或無法開機。

典型順序（⚠ **必須以 datasheet 為準**，這裡先寫框架）：

```
1. VCC_IO  3.3V     先起，讓 IO 有明確準位
2. VDD_SYS 1.1V
3. VDD_CPU 1.1V
4. VCC_PLL 1.8V
5. RESET 釋放        延遲 ≥ datasheet 規定時間
```

實作方式：**用前一級的 PG（Power Good）或輸出電壓經分壓，驅動下一級的 EN 腳。**

```
     3.3V ──[R1]──┬──▶ DC-DC#1 EN
                  └─[R2]── GND     分壓決定觸發門檻
```

驗證方式：**bring-up 時用示波器四通道同時抓四條軌，確認順序與延遲。** 這是第一天就要做的量測。

---

## 4. 去耦電容

原則（依 datasheet，這裡是通則）：

```
每一支電源腳     0.1µF  X7R  0402，緊貼腳位
每一組電源軌     10µF   X7R  0805，靠近進入點
整板輸入端       100µF  電解或鉭質
PLL / 類比軌     額外加磁珠隔離 + 0.1µF + 10µF
```

**注意 DC bias**：上一塊板學到的教訓 —— MLCC 在偏壓下容值會掉。

```
22µF X7R 0805 @3.3V → 實際約 17.6µF（掉 20%）
```

所以標稱值要留餘裕，或直接選大一級的封裝。選型時查 datasheet 的 DC bias 曲線，不要只看標稱值。

---

## 5. 功耗估算

```
T113-S3 全速（2×A7 @1.2GHz）    ~1.5W @ 1.1V → 5V 端約 350 mA（效率 85%）
IT66121（HDMI 工作中）           ~0.5W → 5V 端約 120 mA
RTL8201F（100M link up）         ~0.3W → 5V 端約 70 mA
SD / SPI NOR / 被動              ~0.2W → 約 50 mA
USB-A Host 對外                  5V × 500 mA = 2.5W
──────────────────────────────────────────────────────
峰值                             ~900 mA @ 5V = 4.5W
```

Type-C 5V/3A = 15W，**餘裕三倍以上**。

⚠ 但只用 5.1k CC 電阻時，實際可取電流取決於電源端：

```
標準 Type-C 充電器      可到 3A
USB-A 轉 C 線接電腦     可能只有 500mA  ← 推 USB Host 時會不夠
```

**緩解**：USB-A Host 的 5V 加限流開關（如 TPS2051），過流時只斷 Host 不影響主板。

---

## 6. 熱

上一塊板學到的熱阻模型：

```
R = L / (k × A)      銅 k=385 W/(m·K)，FR4 k=0.30
走線與 via 是串聯，再與「垂直穿 prepreg 到 GND 平面」並聯
```

T113-S3 QFP128 全速功耗 ~1.5W，QFP 的 θJA 通常在 30~50°C/W 之間（依銅箔面積），
預估 Tj 上升 45~75°C。⚠ **需查 datasheet 的 θJA 與最高 Tj**。

緩解手段（依成本排序）：
1. 晶片下方與周圍鋪大面積銅，用多顆 via 連到內層 GND
2. 背面對應位置也鋪銅（散熱面積翻倍）
3. 必要時加散熱片

**驗證**：bring-up 時用熱像儀或熱電偶量，跑 `stress-ng` 15 分鐘達熱平衡後讀值。
上一塊板的教訓是：WiFi 測試只跑 40 秒，沒達熱平衡，數據不能用。

## 7. 量測清單（bring-up 第一天）

```
[ ] 未插 SoC 前（若可行）先量各軌空載電壓
[ ] 1.1V / 1.8V / 3.3V 三軌電壓，誤差 <±3%
[ ] 四通道示波器抓上電時序，確認順序與延遲
[ ] 各軌漣波（AC 耦合，20MHz 頻寬限制），目標 <50mV pp
[ ] 總電流（待機 / 全速 / 插 USB 裝置）
[ ] 15 分鐘後 SoC 表面溫度
```
