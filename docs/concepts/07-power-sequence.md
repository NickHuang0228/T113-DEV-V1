# 概念 ⑦ 上電時序

> 直覺上把所有電壓同時打開最簡單。但 SoC 會規定順序，
> 違反的後果從「開不了機」到「永久損壞」。

---

## 原因一：IO 腳的寄生二極體會倒灌

跟概念 ⑥ 是同一個二極體，只是這次問題出在「電源還沒到」而不是「外部電壓太高」：

```
        VCC_bank
           │
          ─┴─ ▲   上箝位二極體
   PIN ────┼──┤
          ─┬─ ▲
           │
          GND
```

**VCC_bank 還沒上電（= 0V），但外面把訊號送進 PIN：**

```
PIN = 3.3V，VCC_bank = 0V
→ 上箝位二極體正向導通
→ 電流從 PIN 灌進 VCC_bank
```

### ★ 後果分兩層，輕的那層更常見也更難查

```
輕（常見）   電流給 VCC 軌偷偷充電
             → 那條軌爬到不上不下（例如 2.6V）
             → 晶片處於非法狀態，行為不可預測
             → ★ 量電壓看起來「有電」，量晶片也沒燒，但就是不開機

重（少見）   電流太大 → 二極體燒毀，或觸發 latch-up
```

⚠ **如果以為「時序錯 = 燒掉」，板子開不了機時就不會往時序想** ——
因為晶片量起來是好的、電壓量起來也「有」。這種 bug 最耗時間。

**bring-up 的對應動作：用四通道示波器同時抓四條軌的上電波形，不是用電表量穩態。**

---

## 原因二：內部邏輯需要穩定的參考

```
core 電壓（0.9V）   跑數位邏輯
IO 電壓（3.3V）     跑 IO buffer
PLL 電壓（1.8V）    跑時脈產生
```

core 還沒穩，IO buffer 就開始動作 → **輸出狀態是隨機的**。
那些隨機電平會送到 SPI NOR / SD 卡 / PHY，可能被誤判成指令。

**所以順序不只保護晶片自己，也保護外部元件不要收到垃圾。**

---

## T113-S3 的實際要求

```
T1 > 2 ms      VCC-IO 早於 VDD-SYS / VDD-CORE
T2 > 64 ms     RESET 拉低延遲
關機           "No special restrictions for other power rails."
```

**兩個觀察：**

① **這顆晶片的要求異常寬鬆。** 只有「IO 先於 core」一條，關機完全沒限制。
有些 SoC 要求三到五組嚴格按序、還要求下電順序反過來。

② **`T2 > 64 ms` 不是電源時序，是 RESET 時序。**
所有電源穩定後，RESET 還要維持低電平至少 64ms，
讓內部電路（PLL 鎖定、BROM 初始化）就緒。

## 怎麼實作

### 方法 A：EN 鏈（本專案採用）

```
5V ──▶ DC-DC(3.3V) ──┬──▶ VCC-IO
                      │
                      └──[分壓]──▶ DC-DC(0.9V) 的 EN 腳
                                    │
                                    └──▶ VDD-CORE
```

3.3V 起來後，分壓電壓越過 EN 門檻才啟動 0.9V。
**順序由電路本身保證，不需要 MCU 或 sequencer。**

```
優點   零成本，兩顆電阻
缺點   延遲由 DC-DC 的 soft-start 決定，不精確
```

### 方法 B：Power sequencer IC

可程式化每軌延遲。本專案用不到（要求太寬鬆）。

---

## ★ RESET supervisor 不屬於上電時序

那是獨立的一件事：

```
上電時序     各電源軌之間的先後
supervisor   電壓真的到達門檻才放開 RESET，而且掉電時主動拉低
```

**第二句才是 supervisor 真正的價值：掉電保護。**

```
電源瞬間下陷（插拔 USB、負載突變）
  → 掉到 2.8V 但沒掉到 0V
  → 晶片在非法電壓下卻沒重啟 → 當機或資料損毀
  → supervisor 偵測到並強制 RESET
```

### 為什麼不照抄 MangoPi 的做法

```
MangoPi   10K 上拉，沒有 supervisor
          64ms 八成是靠 DC-DC soft-start 湊的

靠 RC 或 soft-start 湊延遲
  → 延遲隨電壓、溫度、批次飄移
  → 「大部分時候能開機」，偶爾開不了  ← 最難查的那種 bug
  → 而且完全沒有掉電保護
```

用 supervisor IC（MCP809、TPS3808 這類）多花幾毛錢，
換掉一個不確定性 + 得到掉電保護。

---

## 一句話

**上電順序的本質是「不要在電源域還沒準備好時送訊號或電流進去」，
後果多半是「非法狀態開不了機」而不是燒毀；
supervisor 管另一件事：電壓合格才放行、掉電時主動保護。**
