# 概念 ⑤ mux 衝突與 0Ω 隔離

> 前四條是電磁學，這條是**系統設計**。

---

## 為什麼晶片要有 pin mux

T113-S3 裡有 6 個 UART、4 個 I2C、3 個 SD 控制器、2 個 SPI……
每個都配專屬腳位的話需要好幾百支腳。

但**沒有人會同時用到全部**。有人要 6 個 UART，有人要 3 個 SD。

所以晶片的做法是：**功能共用腳位，開機時用軟體選一個。**

```
                  ┌─ NCSI0-PCLK
                  ├─ UART2-TX
PE2 實體腳 ──mux──┼─ TWI0-SCK
                  ├─ UART0-TX
                  ├─ RMII-RXD1
                  └─ GPIO
                     ↑ 軟體暫存器選一個
```

---

## ★ datasheet 最大的陷阱

Features 頁寫：

```
Up to 6 UART controllers
Three SD/MMC host controller (SMHC) interfaces
Up to 4 TWI controllers
```

**這是 mux 選項的總數，不是能同時使用的數量。**

> 查證的單位不是「這個功能存不存在」，
> 是「這個功能佔用哪幾支實體腳、還有誰也要那幾支」。

**要查 Pin Multiplexing 表（Table 4-3），不是 Features 頁。**

---

## 本專案撞到的三個衝突

| 衝突 | 腳位 | 誰跟誰 |
|---|---|---|
| MIPI DSI ↔ RGB | PD0~PD9 | 兩個顯示輸出 |
| UART0 ↔ SDC0 / RMII | PF2/PF4、PE2/PE3 | console 撞開機裝置與網路 |
| Parallel CSI ↔ RMII | PE0~PE9 | 攝影機撞網路 |

三個都是「我以為某功能有自己的腳」的結果。

---

## 三種解法

```
① 放棄一個      CSI 砍掉 → 攝影機改走 USB UVC
② 時間錯開      UART0 與 SDC0 —— BROM 階段印 log，之後切給 SD
③ 物理隔離      MIPI 與 RGB —— 10 顆 0Ω 二選一
```

第 ② 種成立的條件：**兩個功能在時間上本來就不重疊**。
BROM 印完 log 才去讀 SD，不是同時。

---

## ★ 關鍵：軟體切 mux，切不掉電氣負載

這是 0Ω 存在的唯一理由。

假設 PD0 直接並接兩邊：

```
T113 PD0 ──┬──────────▶ MIPI FPC
           │
           └──────────▶ ADV7511
```

MIPI 模式下軟體把 PD0 設成 `DSI-D0P`，ADV7511 那條路「邏輯上」沒在用 ——
**但它的輸入腳還是物理連在那條線上。**

⚠ 注意問題的本質：

```
不是「電還是會送過去」（ADV7511 輸入是高阻抗，不吃電流）
是「線還連著」：
  ① 從主幹到它的那段走線 = stub  → 反射（概念 ③）
  ② 它的輸入電容（幾 pF）掛在末端 → 讓反射更嚴重
```

這是**訊號完整性**問題，不是漏電。
如果是「電被分走」，加個緩衝器就解決了；但 stub 反射是幾何造成的，
**只能物理斷開**。

MIPI 臨界長度只有 4mm —— 一條通往 ADV7511 的走線，不管多短都超標。

```
0Ω 裝上  =  導通  →  RGB 模式
0Ω 拆掉  =  斷開  →  MIPI 模式，ADV7511 完全脫離主幹
```

---

## 為什麼不用電子開關（analog mux IC）

```
0Ω / 跳線         被動，切換要動烙鐵，但不加入任何寄生
MUX / bus switch  主動，軟體可切，但自己就帶 5~10 pF 電容
                  + 導通電阻 + 傳輸延遲
```

**在 1 Gbps 的 MIPI 上，那顆開關本身就是最大的阻抗不連續點。**
為了省拆焊的麻煩，反而把訊號搞壞。

規律：

```
低速訊號（I2C、GPIO、UART）  →  可以用 MUX IC，方便
高速差分（MIPI/TMDS/USB）    →  只能用 0Ω，或乾脆分成兩塊板
```

本專案選 0Ω 是合理的 —— **這種板子一輩子可能只切換兩三次**
（驗證 HDMI 時裝上，之後專心做 MIPI），為那幾次犧牲訊號品質不划算。

---

## 代價

```
① 切換要拆焊        不是跳線帽，是真的要動烙鐵
② 焊盤仍是 stub     就算 0Ω 不裝，從主幹到焊盤那截銅永遠在
                    → 規定 ≤ 0.5mm（MIPI 臨界 4mm 的 1/8）
③ 多 10 個料位      BOM 與貼裝成本
```

---

## ⚠ 一個待確認的優化

RGB 路徑本來就要串 **22~33Ω 阻尼電阻**（源端終端，概念 ③），
而那也放在靠近 T113 的位置 —— **跟 0Ω 的位置重疊**。

```
現在的設計   PD0~PD9：0Ω（開關）+ 另外的阻尼電阻？
可能的優化   直接用 33Ω 當開關，一顆做兩件事
```

前提是確認 MIPI 模式下那顆不裝時，焊盤 stub 仍 ≤0.5mm（不受阻值影響）。

**畫原理圖時值得花五分鐘確認。** 如果可以合併，10 個料位省下來，BOM 少一種料。

---

## 一句話

**mux 是共用實體腳，軟體只能改「這支腳歸誰管」，改不掉「線還連著誰」；
而線連著就有 stub，高速時只能用 0Ω 物理斷開。**
