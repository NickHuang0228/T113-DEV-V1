# 概念 ⑥ bank 為什麼會連坐

---

## bank 是什麼

一個 IO bank 共用三件事：

```
① IO 電源域           整個 bank 的 IO buffer 吃同一條 VCC
② 控制暫存器           同一組 CFG / DATA / DRV / PULL / EINT
③ ★ die 上的物理位置   同一 bank 的 IO cell 在晶片邊緣是連在一起的一段
```

**第三項才是「燒一支死一片」的原因。** 前兩項只是管理上的分組，第三項是物理上的相鄰。

### ★ 因果方向不要搞反

```
❌ 先有 bank 分組  →  所以一起壞
✅ die 上 IO cell 物理相鄰  →  一起壞  →  工程師把這自然邊界命名為 bank
```

**bank 不是軟體或文件上的分類，是物理事實。**
所以沒有任何辦法用軟體規避它 —— 就像沒辦法用軟體規避 stub（概念 ⑤）。

---

## 三種連坐機制

### ① ESD 二極體燒穿 → 拉垮整條 VCC

每支 IO 腳都有上下箝位二極體：

```
        VCC_bank
           │
          ─┴─ ▲   上箝位
   PIN ────┼──┤
          ─┬─ ▲   下箝位
           │
          GND
```

外部電壓超過 `VCC + 0.3V` 時上二極體導通 —— **這是正常保護**。
但電流太大會把它燒成**短路**，那支腳就變成 VCC 對外的低阻通路。

```
VCC_bank 被拉低 → 整個 bank 的 IO 全部失效
```

### ② Latch-up 燒掉 die 上一整段（最惡性）

CMOS 的 IO 結構裡有寄生 SCR。過壓觸發後，它在 VCC 和 GND 之間形成
**自我維持的低阻通路** —— 就算外部干擾消失，它還是繼續導通。

```
電流可達數百 mA，集中在一小塊 die 區域 → 金屬連線熔斷
```

**熔掉的不是一個點，是那一段 IO ring。**

### ③ 控制邏輯區受損

少見，但整個 bank 的 mux 會失效。

---

## ★ 高速介面的控制線在 bank 裡

```
不在 GPIO bank（專用 PHY pad，有自己的保護）
  MIPI D0±/CK±、HDMI TMDS、USB DP/DM

在 GPIO bank（一般 IO mux）
  面板 RESET、背光 EN、PWM 調光、觸控 INT/RST
  HDMI HPD / CEC / DDC(I2C) / 5V EN
  USB VBUS EN / OTG ID / 過流 OC
  PHY RESET / MDC / MDIO
```

**一個 bank 死掉，會讓一堆「資料通道其實好好的」介面全部初始化失敗。**

HDMI 差分線完好無損，但 HPD 和 DDC 在燒掉的 bank 上
→ ADV7511 永遠不知道螢幕插上了。

---

## 本專案的災損半徑

| Bank | 拿來做什麼 | 燒了會怎樣 |
|---|---|---|
| **PB / PC / PF**（同一條 VCC-IO） | UART0 log、SPI NOR、microSD | **失去 console + 兩個開機裝置 → 變磚** |
| PD | MIPI + RGB | 顯示全失 |
| PE | RMII | 失去 TFTP/NFS 開發循環 |
| **PG** | 全部給排針 | **幾乎無損失** |

⚠ **PB / PC / PF 三個 bank 綁在同一條 VCC-IO 上。**
那條軌掛著：主要開機裝置 + 備援開機裝置 + 唯一的 log 輸出。
**一掛就變成無法診斷的磚** —— 不是「壞了」，是「壞了但查不出為什麼」。

---

## 兩條設計規則

### ① 對外的腳只放最安全的 bank

排針是全板最容易燒的地方：手滑短路、接錯模組、熱插拔、外部電源倒灌。

```
排針放 PB/PC/PF  →  燒了同時失去 SD 開機 + NOR 開機 + UART log  →  變磚
排針放 PG        →  燒了只失去排針本身
```

這就是 PG 16 支全給排針、並移除 WiFi footprint 的理由 ——
WiFi 的 SDIO1 會吃掉 PG 6 支，等於一個永遠不焊的模組佔用最安全 bank 的 37%。

### ② 每支對外訊號串限流電阻

```
GPIO / UART / SPI     330Ω
I2C                   100Ω   （太大會拖慢上升沿）
電源與 GND            不串
```

為什麼有效：

```
對功能幾乎無影響   CMOS 輸入阻抗 MΩ 級，串 330Ω 不影響準位
對保護影響巨大     誤接 5V 時電流從「無限大」變成 (5−3.3)/330 ≈ 5 mA
                  ESD 二極體撐得住 5mA，撐不住 500mA
```

**約 20 顆 0603 電阻換整個 bank 的命。**
順帶還拖慢邊緣、降低 EMI（概念 ③）。

---

## ⚠ 與 layout 就近原則衝突的規則

```
規則   關鍵控制訊號刻意打散到不同 bank
       （面板 RESET、ADV7511 RESET#、PHY RESET、USB VBUS EN 不要全放同一個）

衝突   layout 的「就近原則」要你把相關訊號放一起
```

**取捨：控制訊號本來就慢，走遠一點沒差，優先分散；只有高速訊號才照就近原則。**

---

## ★ 實務推論：風險分配只有一個時機是免費的

既然 bank 邊界改不了，**你能做的只有決定「把什麼放進哪個 bank」**。

```
pin map 階段   改一支腳的歸屬 = 改一行 CSV      免費
原理圖階段     要改符號、改接線                  麻煩
layout 階段    整塊重拉                          很貴
下單之後       不可能                            $$$
```

這就是 `007-pinmap.md` 開頭「**先做 pin map 才畫原理圖**」的真正份量 ——
它不只是流程順序，是**風險分配只有在那個階段是免費的**。

---

## 一句話

**bank 的邊界是 die 上的物理邊界，改不了；你能做的是決定什麼放進哪個 bank，
而那個決定只有在 pin map 階段是免費的。**
