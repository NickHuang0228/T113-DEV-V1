# 概念 ③ 臨界長度與等長

> 前兩條講了回流和阻抗。但 layout 時面對的是幾百條線 ——
> **哪些要當傳輸線小心處理，哪些可以隨便走？**

---

## 判準是「上升時間」，不是頻率

這是最反直覺、也最重要的一點。

回想概念 ② 的反射：訊號到末端反射回來，來回一趟需要時間。關鍵在於：

```
反射波回來時，原本的訊號邊緣還在變化嗎？
```

```
情況 A：邊緣慢（上升時間長）
        ╱‾‾‾‾‾
       ╱          反射波在邊緣還沒爬完時就回來了
      ╱           → 被「揉進」緩慢的轉換過程，看不出來
     ╱            → 可以當普通導線

情況 B：邊緣快（上升時間短）
     ┌─────       邊緣早就結束了，反射波才回來
     │            → 疊在平坦段上 → 看得到振鈴
     │            → 必須當傳輸線
─────┘
```

**決定因素是邊緣多陡，不是波形多快重複。**

---

## 臨界長度

```
臨界長度 = 上升時間 × 傳播速度 ÷ 6
           （FR4 傳播速度約 150 mm/ns）
```

走線超過這個長度，就必須當傳輸線處理。

本專案的實際數字：

| 訊號 | 上升時間 | 臨界長度 | 要控阻抗嗎 |
|---|---|---|---|
| MIPI HS | ~150 ps | **4 mm** | ✅ 一定要 |
| HDMI TMDS | ~250 ps | **6 mm** | ✅ 一定要 |
| USB 2.0 HS | ~500 ps | **12 mm** | ✅ 一定要 |
| RGB 148MHz | ~1.5 ns | 38 mm | ⚠ 視長度 |
| RMII 50MHz | ~2 ns | 50 mm | ⚠ 視長度 |
| **USB FS（ESP32 那塊板）** | **4 ns** | **94 mm** | ❌ 不用 |

**最後一列解釋了為什麼 ESP32 板的 USB 隨便走都能動** —— 臨界長度 94mm，
而那塊板根本沒那麼大。同樣是 USB，這塊板換成 High Speed，臨界長度掉到 12mm，
完全是另一回事。

---

## ⚠ 不要用時脈頻率判斷

```
一條 1 MHz 的 GPIO，如果驅動器上升時間是 500ps
  → 臨界長度一樣是 12mm，一樣會振鈴
```

**現代 CMOS 的邊緣越來越陡**，就算只跑很慢的訊號，邊緣還是很快。

**看 datasheet 的 `tr` / `tf`，不要看你打算跑多少 MHz。**

### 三個容易混的「速度」

```
資料速率   1 Gbps     每秒送幾個 bit
時脈頻率   148 MHz    每秒幾個週期
上升時間   150 ps     ★ 邊緣從 10% 爬到 90% 要多久
```

**只有第三個決定臨界長度。** 前兩個通常相關但不保證。

---

## 角色分配：誰是輸入、誰是你控制的

```
上升時間 tr    ← 輸入條件。查 datasheet 得到，你改不了
臨界長度       ← 由 tr 算出來的門檻
走線長度       ← ★ 你控制的
阻抗（線寬）   ← ★ 你控制的
```

判斷流程：

```
① 查 datasheet 的 tr       →  MIPI 150 ps
② 算臨界長度                →  150ps × 150mm/ns ÷ 6 = 4 mm
③ 這條線實際要走多長         →  35 mm
④ 35 > 4  →  必須當傳輸線處理
```

**不是「控制上升時間」，是「上升時間告訴你這條線該用什麼規格對待」。**

（唯一例外：串聯電阻可以刻意把邊緣拖慢 —— 排針上那些 330Ω 就有這效果。
但那是降速手段，不是主要工具。）

---

## 「當傳輸線處理」展開是四件事

```
控阻抗    線寬 + 間距照板廠值，整條路徑一致
避 stub   分支短、少、末端別掛大電容
顧回流    正下方連續的銅、不跨分割、換層加 GND via
終端      低速並列自己加源端電阻；高速差分不要碰
```

### stub 的限制手段

```
① 長度      最有效。目標 ≤ 臨界長度的 1/6~1/8
            MIPI 臨界 4mm → 規定 0.5mm
② 數量      每個分支都是一個 stub，能不分就不分
③ 末端負載   stub 末端掛越大的電容，反射越嚴重
```

本專案的 stub 來源：

```
① 0Ω 分支     PD0~PD9 那 10 顆 + PF2/PF4 那 2 顆
② 測試點       PF0/1/3/5 的 JTAG 測試點
③ via stub    訊號從 L1 換到 L2，但 via 穿到 L4，多出來那段
```

### 終端匹配：電阻裝在主幹，不是 stub

```
晶片驅動器輸出阻抗 ~10~20Ω
走線 Z₀            50Ω
                   ↑ 不匹配 → 反射波回到驅動端會再次反射
```

**源端串聯終端**：驅動端串一顆電阻，讓 `Rout + Rs ≈ Z₀`

```
晶片 ──[33Ω]──────────────▶ 接收端
      ↑ 靠近驅動端放
      反射波回來時被吸收，不再彈回去
```

RGB 那 22~33Ω 就是這個，同時做三件事：源端匹配、拖慢邊緣（降 EMI）、抑制 SSO noise。

**但高速差分不用你加：**

```
MIPI D-PHY    接收端晶片內建 100Ω 差分終端
HDMI TMDS     接收端內建 50Ω 到 AVCC
USB 2.0 HS    內建
```

這正是 `002-display.md` 規定「MIPI 線上不能有串聯電阻、不能有 AC 耦合電容」的原因 ——
外加任何東西反而破壞原廠設計好的匹配。

### ⚠ 0Ω 不是終端電阻

```
RGB 的 22~33Ω    終端電阻，功能是阻抗匹配
PD0~PD9 的 0Ω    開關，功能是物理斷開 ADV7511
```

0Ω 裝上就導通、拆掉就斷開，不做任何阻抗上的事。
而 0.5mm 的規定針對**焊盤本身那一小段** —— 就算 0Ω 不裝，
從主幹到焊盤的那截銅永遠在，那是無法消除的 stub。

---

## 等長：解決的是另一個問題

臨界長度回答「要不要控阻抗」，**等長回答「訊號之間到得齊不齊」**。

### ① 對內等長（差分對的 P 與 N）

```
P ───────────────▶  先到
N ──────────╲────▶  晚到
```

差分靠「兩條線的**差值**」傳訊號。P 比 N 早到的那段時間裡，差值是錯的 ——
訊號暫時變成**共模**，抗干擾能力歸零，而且共模電流會直接對外輻射。

**要求最嚴：MIPI ±0.1mm、TMDS ±0.15mm。**

### ② 對間等長（多條線之間）

RGB 的 18 條資料 vs CK、DDR 的資料 vs 時脈。

這是「資料有沒有在時脈邊緣穩住」的問題，容忍度是整個 setup/hold window，
**鬆很多**：RGB 只要 ±5mm。

---

## 關鍵：等長的單位其實是時間

長度只是我們在 PCB 上能操作的代理。

```
MIPI 1 Gbps    一個 bit = 1 ns
               ±0.1mm ≈ ±0.67 ps   → 佔 0.067%   極嚴

RGB 148 MHz    一個週期 = 6.73 ns
               ±5mm ≈ ±33 ps       → 佔 0.5%     寬鬆
```

**同一條規則（±0.1mm）在不同速率下意義完全不同。**
不要背「差分要 ±0.1mm」，要理解那是為了把 skew 壓在一個 bit 的極小比例內。

### 一個容易踩的坑

```
表層走線（microstrip）  一半電場在空氣裡  →  傳播較快
內層走線（stripline）   全部在 FR4 裡     →  傳播較慢
```

**同樣的長度，走不同層 = 不同延遲。** 這是差分對 P/N 必須走同一層的另一個理由。

---

## 一句話

**看 datasheet 的上升時間決定「這條線要不要小心」，再用走線長度和線寬去滿足它；
等長控的是時間，長度只是代理。**
